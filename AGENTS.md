# Reproduce live ChatGPT dictation in OpenWhispr

1. **Identify the right feature.** Use the microphone button in the ChatGPT message composer, not Voice Mode. In browser DevTools, open Network → WS, start a fresh capture, and dictate a short neutral phrase. Pause briefly without pressing Stop, then stop. Look for both streamed microphone frames and text events that arrived before Stop.
2. **Record only protocol facts.** From Headers record the WebSocket host and path locally; note non-secret query parameter names separately. From Messages record event names, order, audio format and field names. In the tested capture, the lifecycle was `session.start` → `session.started` → repeated `audio.append`; the server emitted `transcript.segment` while recording and `transcript.final` on completion. Segment revisions replaced the current utterance's draft rather than appending to it. Recheck these facts on the current version.
3. **Verify upstream independently.** Use the user's own authorized session. The official `codex login` worked for the tested private endpoint, but do not assume it will still work. Try a short public speech sample with fresh session IDs and no existing chat IDs; verify at least one nonempty partial before Stop and a final result after it. A successful WebSocket upgrade alone is not enough. If access is denied, report it and keep the working provider rather than altering browser security or extracting cookies.
4. **Check the installed client before changing it.** In OpenWhispr 1.11.0, generic Self-hosted was batch-only, and the custom Orukeet client did not surface interim results. The Deepgram client already handled interim and final messages. Prefer a configurable streaming URL if the current version offers one. Otherwise use a version-checked, reversible patch that changes only the streaming URL and replaces the outgoing provider credential with a local-only credential. Never forward the real Deepgram key to the bridge.
5. **Bridge and validate.** Bind to loopback and reject unexpected browser origins. Translate the client's PCM format to the observed upstream format (tested: mono PCM16, 16 kHz → 48 kHz). Map each utterance revision to a replacement interim result, and commit each final only once. Drain queued microphone audio before closing upstream. Test the adapter in isolation, then check the widget shows text before Stop and pastes the final once. Keep rollback instructions and leave the original provider settings intact where possible.

## Data handling

Do not copy full HARs, browser cookies, bearer values, account/chat/session IDs, microphone audio, or local settings backups into the repository. Use only public test audio. Never expose Codex credentials to a client or put them in logs or command-line arguments. The upstream interface is unofficial; stop on authorization errors and document a supported fallback.
